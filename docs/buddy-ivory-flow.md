# Buddy Program ivory refinement

Apply the approved Practice Together material system across Buddy entry,
year selection, My Buddy, community posts, recommendations, profile editing,
private questions/replies, coordinator controls and portalled post previews.

The member's job is to find and support a buddy without decoding inconsistent
controls. The old layout had oversized headings and competing panel styles.
Use ease (compact hierarchy), agency (obvious buttons), and attraction
(familiar ivory, gold and pixel art) to reduce this barrier.

Hierarchy: compact header and year setting; existing view tabs; a short school
pairing intro with the existing distinct Buddy pixel illustration; named
buddy cards with current state and action. Community requests retain separate
need and offer sections and explicit preview and response actions.

All states, handlers, copy and evidence remain authoritative. No names are
newly revealed, no counts or badges invented, no automatic confirmations.
The existing role-change recovery, unsaved-change prompts, empty/loading/error
states, reporting, private questions and participation controls are unchanged.
No database or rollout changes. The shared post composer remains functional.

The loop stays: relevant need -> mutual buddy acceptance -> useful support ->
student-resolved request -> next useful interaction. Resolved questions remain
distinct from verified practice exchanges. Measure accepted invitations and
resolved needs, never time spent on these screens.

Cards use fine gold borders and ivory bevels, matcha primary buttons, subdued
secondary controls, consistent sans-serif typography, 44px targets, visible
focus and reduced-motion support. Native post previews stay scrollable with
their close controls at the top. Validate existing Buddy UI tests and build;
real-device visual review remains outstanding.
