# Ask Mutu question-first context

Profile grounding is one capability, not a requirement for all answers. Start with the current question: answer general explanations and writing directly, use relevant authorized records for Buddy, posts, events and past interactions, and consult profiles when personal fit or contributions matter. Missing profiles never block an answer supported by other records. General knowledge must not invent facts about real members. Mixed questions receive a direct general answer plus an evidence-based personal answer. No live web search is added.


The member wants to ask for help without feeling that a professional favor requires an equally professional offer. Previously the assistant received only legacy profile fields, so modern expertise, interests and weekend prompts were absent. Every assistant request now includes an allowlisted view of the current member's profile. Existing profile information is reused without another form. Authorized Community connections can also supply profile evidence; unknown recipients remain unknown.

The behavioral review considered all seven lenses and selected ease (reuse saved information), agency (conditional suggestions and a clear next step), and relevant discovery (explain a suggestion using real interests or expertise). The flow is a question, a grounded suggestion, then an optional personal invitation. Meaningful value comes from making a real connection; future questions can reuse an updated profile and existing relationship memory. There are no scores, obligations or engagement rewards. Success means useful invitations, follow-through and mutually verified exchanges, not time spent in the assistant.

The existing sheet, colors, motion and primary actions stay in place. The introduction reads: “Ask a question, explore an idea or draft a message. When relevant, I can use your profile and Mutu records to make suggestions more personal.” A suggested question reads: “How could I support someone who helps me?” For personal support questions, relevant recipient evidence comes first, followed by one or two optional contributions and a short message when helpful. Other answers follow the question and do not automatically add reciprocity suggestions. Existing loading and retry states remain; unavailable profiles are marked explicitly, and late responses after account changes are discarded. Profile changes refresh grounding. Replies remain private in the existing Ask Mutu history.

Privacy boundaries remain unchanged: no directory search, hidden identities, private peer notes, email addresses or account metadata are supplied as profile context. Block lookup failure withholds connections. Public or mutually revealed Community connections may contribute allowlisted fields; a confirmed Buddy name alone does not establish their skills. The assistant must distinguish the current member's interests from the recipient's, self-reported experience from verified interactions, and a hobby from teaching qualifications. Suggestions are optional and helping never depends on reciprocation. Existing anonymous behavior, rollout flags, canonical taxonomy and database schema are unchanged.

## Validation

Regression coverage includes modern and legacy profiles, intentionally cleared modern fields, two users with different hobbies, own-profile changes, unavailable or mismatched profiles, late responses after account changes, blocked and anonymous connections, payload compaction retaining the named recipient and own profile, and the server's grounding instructions. Model-call tests inspect the actual outbound request with a mocked provider, not the quality of a live generated answer.

Manual acceptance examples: ask about Thomas with a yoga-weekend profile, then with a cooking profile. Suggestions should change with the profile. With no Thomas expertise record, the answer must not certify his interview ability. With no personal interests, it should not invent a hobby. Yoga should mean a conditional invitation to join, never a claim that either person teaches it or that Thomas enjoys it.

Build passed. Ask Mutu regression tests passed (58 tests). The earlier full suite run recorded 589 passing and 10 failing tests; eight failures reproduce on the unchanged base revision in unrelated practice and Buddy tests. The other two pass when their test files run separately, on both base and changed code. This is not a fully green repository suite.

Question-first regression scenarios cover general explanations with no profile, generic writing with irrelevant hobbies present, Buddy facts from records without a profile, and mixed general and personalized questions.

## Profiles explicitly shared with the viewer

Ask Mutu has a separate Shared profiles reader. The previous connection list deliberately excluded already-met people, and ChatView's profile card fetched only identity fields. Neither is a complete source for personal profile questions. The new read-only authenticated endpoint loads profiles attached to accepted Show profile relationships, independent of encounter categorization or Community/Buddy/practice origin. No database migration is required.

The endpoint derives the viewer from a verified session token, reads only that viewer's accepted active/completed matches, deduplicates peers, checks blocks in both directions on the server, and allowlists returned profile fields. Service access is needed because client block policies hide incoming blocks. Public names, pending sharing and practice counts alone never grant this endpoint's access. Email and account fields are excluded. The response is not cached. Each new question and each opening/refresh of Shared profiles rechecks access; failures replace cached profiles with an unavailable state. Profile data remains an optional source for relevant questions.

UX: reuse consent already given and let the viewer inspect the evidence directly. The selected lenses are ease (one visible Shared profiles button), agency (explicit refresh, back and readable source fields), and relevant discovery (search by name/program). The list shows real saved interests and weekend prompts without an AI paraphrase. Empty, loading, failed and missing-interest states are distinct. Native expandable cards support keyboard interaction; no animation or pressure to share is added. The loop is a question, inspect a shared profile, then an informed optional conversation. Success is a useful connection, not clicks or time spent. The existing anonymous/reveal boundaries, profile-independent answers and profile-sharing controls are preserved.

Tests cover paging, met-person inclusion, multiple chats per peer, missing fields, permission and block failures, both block directions, deduplication, withheld profiles, authenticated viewer scope, stale auth sessions, per-question refresh after revocation, profile UI, and named-profile retention in a large AI payload. AI tests use synthetic profiles and do not verify Serine's real account data.
