# Open a full profile from a conversation

A member wants to tap the name/avatar/profile label already visible in a chat and learn about that person. Previously only accepted identity reveals made the header tappable, and the profile card displayed only name, email and program. The new header button opens a complete scrollable member profile with background, industry experience, expertise, needs, interests, activities, connection preferences and all personal prompts. Full text is preserved; this UI does not use the AI context's truncation limits.

The behavioral review selected ease (one familiar entry point), agency (close, retry and explicit sharing), and relevant discovery (professional and personal context). Native dialog focus management, Escape dismissal and a visible close button return the user to the conversation. The interface uses the existing warm white, gold and green palette, with a 480px desktop drawer and a full-width phone panel. No decorative motion is added. The useful loop is inspect a profile, ask a relevant question, then have a real conversation. Success means more useful conversations and completed exchanges, not more profile views.

The server derives the viewer from the session, verifies participation in the requested active/completed match, checks blocks in both directions, and returns only member-profile fields. An accepted identity reveal permits the shared private profile and the existing email field. A genuinely public profile is available in a non-anonymous post connection; email remains excluded until explicit sharing. A public name on a private-profile member's named post is not a full-profile grant: the panel explains this and offers the existing sharing flow. Anonymous posts and source-specific identity flows remain protected. No account metadata, other people's conversations or database changes are involved.

Loading, unavailable, consent-required and complete states are distinct. Every open rechecks current access. Late responses from other conversations or accounts are discarded. Tests cover the header-to-profile path, full detail rendering, close/retry, anonymous headers, the sharing action, stale response isolation, authentic viewer scope, public-versus-named privacy, blocks, inactive matches and database failures.
